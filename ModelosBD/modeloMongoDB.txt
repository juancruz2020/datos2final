INDICES Y RESTRICCIONES FISICAS
El código Java no ejecuta createIndex ni configura validadores JSON Schema. El script de esta carpeta reproduce ese alcance: no añade índices únicos o secundarios que el arranque no crea.
Las colecciones conservan el índice estándar de _id de MongoDB. Las referencias anteriores no son claves foráneas declaradas.
No hay sharding, clave de partición ni replica set declarados en Docker Compose o en los DAO. Docker Compose levanta un servicio MongoDB con un volumen de datos.

VALIDACIONES DE APLICACION
ClienteService: campos obligatorios y comprobación de CUIT existente antes de insertar o modificar.
UsuarioService: existencia del rol, formato ObjectId del cliente cuando corresponde y comprobación de email existente. No consulta la existencia del cliente en la creación. AutenticacionService compara el texto de contraseña; el nombre contraseña_encriptada no implica que exista cifrado o hash.
RolService valida el formato de ID y la descripción para consultas; no expone alta de roles. ContenedorService comprueba código existente. ContenedorService exige capacidad positiva y crea el estado DISPONIBLE.
DisponibilidadContenedores y ContenedorMongoDAO: reserva atómica con estado EN_USO y envio_asignado; restauración de reservas ante fallo del guardado en Neo4j; liberación al eliminar, quitar del envío o pasar a un estado que no ocupa.
FacturaService exige un importe mayor a cero y un cliente existente. Los DAO de pagos y cuentas corrientes no implementan una liquidación contable automática.
MensajeService exige pertenencia a la conversación al enviar y autoría al modificar o eliminar. ConversacionService usa PRIVADA y GRUPAL.
Estas comprobaciones Java no sustituyen una restricción única de base de datos frente a escrituras concurrentes o externas.

REGLA DE DISPONIBILIDAD
EN_USO solo para EN_TRANSITO o DEMORADO. PENDIENTE, ENTREGADO y CANCELADO dejan DISPONIBLE después de guardar. El selector de nuevos envíos muestra DISPONIBLE; en edición puede mostrar el propio EN_USO.
La aplicación permite varios contenedores por envío. Los datos de prueba tienen exactamente un contenedor distinto para cada uno de los ocho envíos.
ContenedorMongoDAO también admite ACTIVO en la reserva como compatibilidad; el selector no ofrece ese estado.
